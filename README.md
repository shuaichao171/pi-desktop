# Pi Desktop

基于 [Pi coding agent](https://github.com/earendil-works/pi) SDK 的桌面工作台，提供 Windows、macOS 和 Linux 构建。界面布局参考 ZCode；Agent、模型、工具、扩展与会话文件仍由 Pi 管理。本项目独立开发，未修改 Pi 的工具执行与审批逻辑。

## 功能

- 流式对话、Markdown、完整的消息与工具调用时间线；参考 Codex 按轮展示中间输出、思考和工具调用，进行中显示实时耗时，整轮结束后自动折叠过程，最终回答保持可见；展开后可阅读思考、命令、输出与差异，支持复制、换行和搜索定位
- 展示模型接口实际提供的思考文本，支持历史恢复、取消和失败状态；没有思考文本时显示等待状态，签名、加密与 redacted 内容不会作为思考展示
- 输入框右侧独立选择模型与思考强度；模型选择框以按钮为中心向上弹出，左侧切换已配置供应商、右侧选择模型，支持跨供应商搜索；底部列出未配置供应商，并提供添加供应商和模型管理入口；悬停查看 Pi 上下文用量／容量和操作提示、中止生成，以及忙时 follow-up / steer
- 设置中的“模型管理”以供应商导航和详情两栏管理连接、凭据和模型；自定义连接直接编辑并保存，添加／编辑模型使用独立对话框；支持供应商模板、获取模型后选择导入，以及未保存修改提醒
- 图片、文本附件及文字 PDF 提取；图片进入 Pi 的图像输入，文本内容附在提示词中，正文、附件与上下文草稿按工作区和会话持久保存
- 输入框 `＋` 或 `@` 添加上下文：搜索、浏览并引用项目文件／文件夹，引用当前项目的历史对话，支持键盘选择和移除标签
- 输入框以 `/` 搜索和补全指令：新建会话、压缩上下文、重命名、重新加载，以及当前 Pi 环境实际加载的扩展指令、提示词模板和技能
- 多工作区项目树与会话列表；顶部后退／前进可回访最近打开的项目和会话（Ctrl／Cmd + `[`、`]`），侧栏收起后搜索按钮位于前进按钮右侧；切换时保留后台 Pi 运行环境，可重命名、置顶、归档和标记未读
- 单击顶部会话标题选中并编辑名称，Enter 保存，点击框外或按 Esc 取消；新建空会话也可命名并在重启后恢复
- Pi 扩展的通知、选择、确认、输入与编辑交互；侧栏插件页集中管理扩展包、技能、提示词与终端主题，支持搜索筛选、详情、资源启停和文本预览
- 插件发现页查询 npm 上真实的 Pi 社区包；支持从 npm、HTTPS Git 仓库或本地目录安装到全局／当前项目，并更新或移除已配置插件
- 本地自动化：任务模板、搜索和状态筛选，选择项目／模型／思考强度，按每日、工作日、每周、间隔或单次时间运行；支持补跑宽限、派发前失败重试、计划次数上限、暂停恢复和历史结果会话
- 工作台文件树、UTF-8 文件预览、Git 状态和差异、单条命令面板，以及独立的交互式 PTY 终端
- 精确选择全部改动或仅暂存内容提交；最近完成回合的文本文件检查点、独立工作树任务，以及普通推送和 GitHub 草稿 PR 交付
- 对话中工具修改文件后，运行时在输入框上方显示紧凑的文件数与增删统计；结束后在对话末尾显示本次对话累计变更卡，默认列出前三个文件并可展开更多；支持审查快照差异、键盘切换文件、复制路径／差异和自动换行，记录随会话保存
- 可调整宽度的侧栏、深色／浅色／跟随系统主题、中英文界面、启动画面和单实例窗口；统一表面与动效，侧栏和工作台平滑切换，分段选项滑动背景，输入框默认多行、工具栏独立位于下方，随内容增高并支持附件，遵循系统减少动态效果设置
- 设置 → 外观支持默认、石墨、海洋、森林、暖沙配色，以及强调色／背景色／文字色和对比度自定义；浅色与深色方案独立保存，实时预览并应用，可单独恢复默认
- 设置 → 个性化可编辑用户主目录的 `AGENTS.md`；已有 Pi 全局指令时，提供独立编辑区（遵循 `PI_CODING_AGENT_DIR`，优先 `AGENTS.override.md`）。支持保存快捷键、外部修改冲突检测和未保存提醒；Pi 全局文件缺失时不创建该入口
- 设置页中的更新状态，以及独立的“检查更新”和“安装更新”按钮；检查只查询版本，安装按钮触发下载、安装并重启，默认通过本仓库 GitHub Releases 获取更新

对话耗时从接收请求、进入准备阶段开始，持续到工具调用、重试和回答全部结束；切换会话或恢复历史不会重置计时。旧会话没有起止记录时不推测耗时。展示规则与验证范围见[对话过程与计时](docs/specs/CONVERSATION_PROCESS.md)。

本轮新增入口如下，完整行为和验证范围见[功能改进记录](docs/FUNCTION_IMPROVEMENTS_2026-09-26.md)。

| 入口 | 功能 |
| --- | --- |
| 输入框与待发送队列 | 恢复正文、附件和上下文草稿；浏览已发送文字历史；编辑、删除、暂停和同类排序待发送输入，重启后的未确认项须明确确认才重新排入 |
| 全局搜索 | 会话增量索引、分页与工作区／日期／归档／分支筛选；项目文件内容搜索可定位行列 |
| 设置 → 数据管理 | 回收站恢复与确认清理、Pi 原生会话导入、完整备份导出／恢复、搜索规则与索引重建，以及用量、存储空间和脱敏诊断导出 |
| 设置 → 模型管理／项目默认值／MCP | 用保存的连接做实际模型请求测试；管理可信项目的默认模型与思考强度；配置、测试和连接 stdio／Streamable HTTP MCP 服务 |
| 工作台 → Git／PTY | 回合检查点、独立工作树、推送／草稿 PR；在当前工作区启动交互 Shell，支持输入、窗口调整和 Ctrl+C |
| 侧栏 → 自动化 | 设置补跑宽限、派发前重试与计划次数上限，查看跳过、重试和完成记录 |

命令面板运行**单条命令**（Windows 使用 PowerShell，macOS/Linux 使用 `/bin/sh`），每次运行前显示工作区和完整命令供确认。独立的“PTY”页签提供交互终端，切换页签或收起面板会保留进程，明确终止或退出应用时清理所属进程；同一时间只保留一个绑定工作区的终端。终端与命令均以当前用户权限运行，Pi 工具原有的执行与审批逻辑不变。文件预览限制为 1 MB；Git 差异分开显示已暂存和未暂存的改动，正文合计最多 1 MB，同时存在两类改动时各保留最多 512 KB，超出时提示截断。插件变更需要所有已加载会话和自动化空闲，并同步重新加载已打开的 Pi 会话；缺失包或加载失败会显示诊断。

添加上下文时，文件和文件夹作为路径引用交给 Pi 按需读取；文件夹附带最多 200 项直属条目概览。对话引用只包含所选会话当前分支的用户与助手正文，最多 100,000 字符，超出时保留最近内容并标明截断。每条消息合计最多 12 项上下文和附件；未发送的正文、上下文标签和附件随会话草稿持久保存，重启后可恢复。附件缺失会明确提示并阻止发送，避免悄悄丢失输入。PDF 仅在本地提取已有文字并保留页码，支持最多 20 MiB、100 页；扫描件不提供 OCR，加密、损坏及超限文件会显示原因。

任务进行中，默认按 Enter 排队发送，Ctrl+Enter（macOS 为 ⌘Enter）引导当前任务。队列参考 Codex 使用紧贴输入框的单行列表，行末提供引导、删除及更多操作，可拖动或用键盘调整同类型消息顺序，点击摘要查看全文与附件名称。编辑进入主输入框区域，原消息暂时退出执行队列；保存回原位置，取消恢复原内容，普通草稿和原附件均保留。更多菜单可关闭默认排队，此时 Enter 与 Ctrl／⌘Enter 的忙时行为互换。暂停队列只暂停后续输入；停止任务后未发送项继续保留。重启后的未确认项由用户选择重新排入或删除。详见[排队指令](docs/specs/COMPOSER_QUEUE.md)。

文件变更卡展示当前会话所选分支中 `edit`、`write`、`bash` 和 `powershell` 工具记录的累计差异，并标注“本次对话”；没有记录时隐藏。运行中的紧凑摘要可打开文件列表，结束后摘要移到对话末尾成为卡片：单文件直接显示文件名，多文件默认列出前三项，可展开其余文件。点击标题、“查看更改”或文件行打开审查窗口；窗口显示工具记录的快照差异，运行中收到新记录会更新，不会重新读取当前工作区或 Git 差异。文件列表支持方向键、Home／End，Esc 关闭；可复制路径、复制原始差异并切换自动换行。展示规则与验证入口见[对话文件变更](docs/specs/CONVERSATION_FILE_CHANGES.md)。

变更基准来自工具执行前的实际文件，不使用 Git HEAD，因此不会把工具执行前已有且未变化的修改计入。连续工具修改会累计；两次工具间检测到外部编辑时，该文件会从新的基准重新记录。记录随 Pi 会话保存，旧版本会话无法补回未记录的执行前内容。命令工具在 Git 项目中遵循忽略规则，普通目录跳过依赖与常见构建目录；仅追踪工作区内的普通文件，文件数、读取量与预览大小均有上限，超大项目的命令变更记录可能不完整。二进制与较大文件显示预览说明；未知增删行数不会显示为零，汇总只包含部分文件时以星号说明。

在输入框开头输入 `/`，使用方向键选择，Enter／Tab 补全指令，再填写参数并发送。例如 `/new`、`/compact 重点保留接口约定`、`/name 修复登录问题`、`/reload`；技能使用 `/skill:名称`。内置操作需要等待当前任务完成；模板和技能在忙时可以排队或引导当前任务。内置操作与扩展指令不接收附件，提交失败时会保留草稿；提示词模板与技能可携带附件和上下文。

侧栏“自动化”中的任务在本机执行，需要应用保持打开且电脑唤醒。每次运行创建独立 Pi 会话和执行进程，不切换当前对话；最多同时运行两个任务，同一任务不会重叠。休眠或退出期间错过的计划在恢复后最多补一次，再推进至未来；可设置补跑宽限，超出宽限则记录跳过。立即运行不改变定时计划，暂停只影响后续调度，停止按钮取消当前运行。单次计划触发后自动停用，重复计划可设置次数上限；仅明确尚未派发的失败按配置重试，已经交给模型执行的任务不会因此自动重放。间隔支持 5 分钟至 30 天；重复日程按所选 IANA 时区计算，夏令时回拨不重复运行，跳时跳过不存在的时间。

自动化沿用已保存的项目信任与模型配置；需要新交互确认的扩展会停止任务并记录原因。单次执行最长 30 分钟，重启后未完成的记录显示为中断。配置及最近 200 条运行历史保存在应用数据目录的 `automations.json`；损坏文件保留原样并显示错误，存储写入失败时暂停派发并重试。任务模板只预填表单，保存后才建立计划。

详细实现、参考来源及验证范围见[自动化模块](docs/AUTOMATIONS.md)。

侧栏“插件”管理 Pi SDK 的包与资源；Codex／ZCode 作为界面参考，其插件格式不直接兼容。发现页按相关性展示最多 24 个带 `pi-package` 标签的 npm 包，可继续搜索。技能和提示词提供最多 64 KiB 的只读文本预览；终端主题不会改变桌面外观。本地插件从原目录读取，移除只取消配置；远程安装需要系统可用的 npm／Git。详见[插件模块](docs/PLUGINS.md)。

## 架构

```text
React UI ── window.piDesktop ── Electron preload ── Electron main
                                                     ├─ 工作区 / Git / 命令服务
                                                     └─ utilityProcess RPC ── Pi SDK / AgentService
```

Pi SDK 在独立的 Electron utility process 中运行，避免 SDK 初始化或工具运行阻塞主窗口。主进程负责原生窗口、文件夹选择、项目信任提示和受限的 IPC 桥；渲染进程不直接访问 Node 或 `ipcRenderer`。

Electron ESM preload 的兼容性要求关闭窗口 sandbox；窗口仍启用 `contextIsolation`，preload 只暴露定义好的 `window.piDesktop` 桥接方法。主进程校验工作台文件路径，并在执行单条命令面板中的命令前再次确认。

| 目录 | 职责 |
| --- | --- |
| `packages/agent` | Pi SDK 会话运行环境、事件与附件适配 |
| `packages/shared` | 主进程、preload 与 UI 共用的类型和通道契约 |
| `packages/desktop` | Electron 壳、utility process、工作台服务和打包配置 |
| `packages/ui` | React 界面、状态管理与双语文案 |

`reference/` 仅作设计参考，已从 Git 和安装包排除。

Pi SDK 通过 npm 精确版本和锁文件管理；上游版本的检查、升级 PR 与验证流程见[与 Pi 上游同步](docs/PI_SYNC.md)。

## 开发

需要 Node.js ≥ 22.19、pnpm 11.11.0，以及对应平台的构建环境。Windows 目标支持 Windows 10/11。首次安装会从 Electron 官方发布源下载运行时。

```bash
pnpm install --frozen-lockfile
pnpm dev
pnpm typecheck
pnpm test
pnpm build
```

模型和凭据沿用 Pi CLI 的 `~/.pi` 配置。首次默认工作区是 `~/PiDesktopWorkspace`，之后会恢复上次工作区及其 Pi 会话。打开包含 `.pi` 或 `.agents` 项目资源的文件夹时，应用会询问是否信任；持久化选择由 Pi 的 `ProjectTrustStore` 管理。不信任仍可打开文件夹，但不加载该工作区的设置、技能和扩展。

“个性化”直接保存指令文件，不改变 Pi 的加载规则：用户主目录 `~/AGENTS.md` 仅由位于该目录下的项目继承；Pi 配置目录（默认 `~/.pi/agent`）的全局指令适用于所有项目及 Pi CLI。保存后新建对话会读取新内容，已有对话可在空闲时发送 `/reload`，也可重启应用。文件名使用 Pi 支持的复数 `AGENTS.md`，不创建单数 `AGENT.md`；每个文件最多 128 KiB。

在“设置 → 模型管理”中选择供应商，可查看其模型并管理 API Key；也可从对话框的模型选择列表直接进入。未配置凭据的供应商单独列在底部，点击即可配置；已有登录凭据或环境变量的供应商仍可使用。“添加供应商”支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Gemini 协议；填写服务的基础 URL，并添加至少一个实际模型 ID，可设置显示名称、上下文容量、最大输出、思考和图片输入能力。自定义配置保存到 Pi 的 `models.json`，密钥单独保存到 Pi 凭据存储，不会回显；编辑时密钥留空保留原值。保存后模型列表会刷新，所有已加载会话空闲时才允许修改配置。外部高级配置保留原有内容，界面无法完整表达的配置只读显示。

自定义供应商的名称、URL 和协议在详情中直接编辑，点击保存后生效；取消仅还原连接修改，API Key 单独保存。添加或编辑模型在独立对话框中完成，失败时保留草稿。切换供应商、设置分类、刷新或关闭设置时，未保存的修改会提示确认；当前使用中的模型不能关闭显示开关。

新建供应商时，可选择模板并获取模型；已有供应商的“获取全部模型”会打开独立导入对话框，使用已保存的连接从模型列表接口分页读取并选择导入。同 ID 的现有模型保留手动参数；供应商明确返回的上下文、最大输出和思考强度会填入预览，未提供的能力不按模型名称猜测，默认参数可手动修改。获取操作不自动保存，不支持模型列表接口的服务仍可手动添加。高级配置可设置自定义请求头，已保存的值不回显、留空保留，移除行会删除该请求头；新值按字面保存，不执行 Pi 的环境变量或命令模板。

供应商可开启“使用系统代理”或关闭后直接连接，模型获取与四种协议的聊天请求均使用此设置，下次请求生效；旧供应商未设置时沿用 Pi 的网络行为。系统代理读取本机操作系统配置，支持 HTTP/HTTPS 代理及直连规则；SOCKS 会提示不支持，可在代理软件中启用 HTTP 代理。此开关只控制桌面端，不修改操作系统代理，也不改变 Pi CLI 的网络设置。

若工作区、会话标记或语言设置文件损坏，应用会把原文件保留为 `.corrupt-*.bak` 备份并提示路径，再使用默认设置继续。可从备份手动恢复之前的工作区列表或会话标记。

## 打包与发布

Windows 上可双击根目录的 `build.cmd` 一键安装依赖、校验 Pi SDK 版本、运行类型检查与测试，然后生成安装版和便携版 EXE。需要 Node.js ≥ 22.19 和 pnpm 11.11.0；首次构建会下载 Electron。构建成功后会输出产物路径；脚本结束时自动退出，双击启动的窗口会自动关闭，无需按键。

双击根目录的 `release.cmd` 可一键发布：默认把补丁版本加一（如 `0.1.1` → `0.1.2`），同步两处应用版本，完成本地校验后提交并发布**整个当前工作区**。所有未被 Git 忽略的新增、修改和删除都会通过 `git add -A` 一起提交。需要位于 `main` 分支、`origin` 指向本公开仓库，并已通过 `gh auth login` 登录 GitHub；脚本会检查 Node.js、pnpm、Git 和 GitHub CLI。

```powershell
.\release.cmd --dry-run  # 只读预览，不修改文件、Git 或远程
.\release.cmd            # 默认补丁版本 +1，并完成发布
.\release.cmd 0.2.0      # 指定更高的稳定版本
```

发布脚本会原子推送 `main` 和版本标签，等待对应的 `Desktop release` 工作流完成并校验草稿产物，再自动公开 Release、设为 Latest。安装包在 GitHub Actions 构建，需要保持联网；Windows／Linux 始终构建，macOS 需要完整签名与公证凭据。失败后再次运行原命令会接续同一版本；CI 失败可用 `--retry` 重跑同一提交，需要修改源码时使用 `--reset` 清除本地发布进度后修复并发布新版本。双击运行的发布窗口结束时会暂停，方便查看结果。其他平台可运行 `node scripts/release.mjs`，参数相同；恢复行为与手动发布步骤见[发布指南](docs/RELEASE.md)。

```bash
pnpm pack:dir  # release/win-unpacked/
pnpm dist:win  # 安装版 + 便携版
pnpm dist:mac  # macOS：当前机器架构的 DMG + ZIP；CI 分别构建 x64 / arm64
pnpm dist:linux # Linux：AppImage + DEB，x64（在 Linux 上运行）
```

输出位于 `release/`。Windows 的 Portable 是单文件自解压包，每次启动都要先解压 Electron 和应用文件；解压期间会显示原生启动图。日常使用推荐安装 Setup 版，从其快捷方式启动可跳过每次解压，并支持软件内更新。打包默认嵌入本仓库公开 Releases 地址，同时生成 `latest.yml`；Portable 需要手动替换。此前未配置更新源的 `0.1.0` 需要手动安装一次新的 Setup，之后才能接收更新。Windows 应用图标源文件是 `packages/desktop/build/icon.svg`，可运行 `python scripts/make-icon.py` 重新生成 PNG 与 ICO（需要 Pillow）。启动 Logo 位于 `packages/desktop/src/main/splash.ts`；`pnpm dist:win` 会直接从该 SVG 生成便携版启动图，也可单独运行 `node scripts/make-portable-splash.mjs`。便携版启动器启用 DPI 感知，图标按原生像素显示，避免 Windows 放大位图造成模糊。

双击根目录的 `debug.cmd` 可在本地构建调试用的便携版（输出到 `release-debug/`，无需发布）：独立的 "Pi Desktop Debug" 身份，userData 与正式安装互不影响；便携模式自动停用更新检查，不会误升级到线上版本；`run-debug.cmd` 以远程调试端口 `9223` 启动，便于用 CDP 检查 UI，`win-unpacked/` 里的 EXE 可免解压快速运行。打包在仓库外的暂存目录完成，避免编辑器/代理的文件监视锁住中间产物；若旧产物被占用无法替换，重启相关软件后手动删除即可。

启动时并行加载界面和恢复会话，历史消息绘制完成后再从 Logo 切换到主窗口，避免先显示空对话。若初始化需要扩展交互，会先显示对应弹窗；初始化失败时显示错误提示。

提交到 `main` 或提交 PR 会触发多平台 CI。单独推送与应用版本一致的稳定 `vX.Y.Z` 标签会创建**草稿 Release**；一键发布脚本负责等待、校验并公开该草稿。手动运行发布工作流时也可开启 `publish`，通过产物校验后自动公开并设为 Latest。公开 Release 即为默认更新源，无需额外服务器；本地 `0.1.0` 用户需先手动安装新版 Setup。具体步骤与升级验证见 [发布指南](docs/RELEASE.md)。

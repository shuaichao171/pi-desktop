# 插件模块

侧栏“插件”提供 Pi 包和资源的统一管理页面；设置中的扩展入口也跳转到此页面。参考 Codex 的已安装／发现分区和安装流程，以及 ZCode 的卡片、详情与资源清单，使用项目既有配色、分段切换、轻量入场和开关动效。

## 功能与范围

- 已安装页同时显示配置的包和独立资源，区分全局／当前项目，支持按名称、来源、资源类型、启用状态筛选。详情返回后保留查询和滚动位置。
- 详情显示版本、来源、路径及扩展、技能、提示词、终端主题。资源分别显示配置启用状态、当前运行环境加载状态和错误；Pi 不提供统一的整包启用字段，因此只展示真实资源开关。
- 技能与提示词提供只读文本预览，最多读取 64 KiB 并标记截断，不渲染其中的 HTML。终端主题仅作用于 Pi 终端，不改变桌面主题。
- 发现页主动请求 npm 官方搜索 API，最多展示 24 项，并允许关键词搜索。只有带 `pi-package` 标签、名称和版本有效的结果进入安装表单；安装来源预填为明确版本。目录是社区元数据，未将示例或推荐卡片伪装成真实插件。
- 支持 `npm:package@version`、不含凭据的 HTTPS Git 仓库地址，以及原生目录选择器选取的本地目录；安装范围可选全局或受信任的当前项目。npm／Git 下载与安装使用 SDK 和系统工具，没有另建安装器。
- 更新与移除均需页面确认。SDK 按来源身份更新全局和当前项目中的匹配安装，更新提示明确说明这一范围；固定版本保留约束。本地目录隐藏更新按钮，变更源文件后重新加载即可。移除本地插件不删除原目录；缺失或损坏的包配置仍可移除。
- 当前项目的写入沿用 Pi 信任状态。单文件本地包因 SDK 不支持单资源过滤，显示不可单独切换，不报告假成功。

## 生命周期与可靠性

读取目录和预览使用 `resolve(... => 'skip')`，不会隐式安装缺失包。预览必须匹配当前项目解析出的资源路径、类型和作用域。配置写入检查 SDK 的错误队列，避免吞掉保存失败。

插件变更先同步占用操作，再锁定全部已缓存 Pi 会话；生成、导航、模型和配置变更不能交叉执行。成功写入后预检所有上下文，再逐个重新加载，清理停用扩展遗留的模型供应商；失效模型要求重新选择。缺失包阻止自动重载并显示“已保存、未重载”诊断，加载失败则阻止使用旧的半完成运行环境，直到修复并重新加载。

主进程验证调用窗口、主框架及当前项目。插件变更、旧扩展开关和 `/reload` 使用相同的自动化维护门禁：已有任务运行时拒绝修改，维护期间延后新计划且不消耗日程。自动化执行进程未确认退出时保留占用，阻止新执行并提示重启。

SDK 安装没有可公开使用的取消信号，因此安装过程中禁用重复提交和关闭表单，等待真实结果后再释放锁；应用退出仍使用既有的有限等待和进程清理流程。请求结果绑定桥接实例、项目及会话，旧请求不能覆盖新的页面。插件页不卸载聊天视图，草稿保持可用。扩展交互使用原生模态层，初始化确认可以显示在忙碌的安装弹窗之上，避免双方互相等待。

# 懒加载悬停摘要与未聚焦轮询降频

本规范对应两项渲染层性能行为（借鉴 Claude Desktop 逆向观察：hover_card 懒探测 + 会话轮询门控）。不新增设置项，行为对用户透明。

## B5：会话行悬停摘要懒加载 + 静默降级

- 侧栏会话行悬停约 300ms 后在侧栏右缘弹出预览卡片：标题 + 最近一条用户消息与最近一条助手消息的首行摘要（各最多 240 字符、两行截断）。键盘聚焦行立即打开（无延迟）。
- **延迟触发**：`HoverTooltip` 新增 `openDelayMs`；快速划过列表（指针在延迟内离开）不打开卡片、不触发任何加载。已打开提示的互斥/层级/Escape 行为与既有提示一致。
- **内容懒加载**：首次实际打开（`onOpen`）才发起一次 `data:sessions:preview` IPC；当前正在查看的会话直接从内存消息计算，不走 IPC。
- **缓存**：结果以 `path + modified`（修订键）缓存在渲染层（上限 200 条，先进先出）；主进程侧复用搜索索引的会话解析缓存（指纹校验：大小/mtime 变化才重读），同一修订绝不重复读盘。
- **静默降级**：读取失败（含 403/404 语义的无效/越权路径）解析为 null 并缓存，卡片只显示标题；不弹错误、不闪 loading、同一修订不重试。会话内容更新（modified 变化）后下一次悬停重新加载。
- 摘要取**被查看分支**（分支记忆 store）链路上的末条用户/助手消息；未记忆分支时取最新叶子链，与 `readSessionContext` 语义一致。归档行同样有预览；未保存草稿行不预览。

## B6：未聚焦降频轮询 + 空闲截止

- 共享调度器 `focusAwarePolling`（纯逻辑，可单测）：窗口聚焦 → 基础间隔；未聚焦 → 间隔 ×3；持续未聚焦超过 10 分钟 → 暂停（不排定时器）；重新聚焦 → 立即刷新一次并恢复正常间隔。
- 聚焦感知复用提示音功能同一信号（window focus/blur，`document.hasFocus()` 初始值）。
- 应用于**非关键**轮询点（`ConversationMetrics`）：供应商用量查询（用户配置的间隔分钟数）、会话统计 busy 期间的 1s 刷新。二者已有并发去重（pending 标记），聚焦触发的立即刷新复用同一入口。
- **不适用**（时间敏感/事件驱动）：自动化调度器（automationService 定时器）、托盘刷新（revision 驱动）、应用更新检查（主进程 4h）、会话运行时状态（事件推送，非轮询）、相对时间显示 tick。

## 验证

- `tests/session-preview.test.mjs`：首行摘要提取（空白折叠/截断/代理对）、内存摘要、缓存去重与静默降级（失败缓存 null、同修订不重试）、容量上限、分支头感知提取、接线约定。
- `tests/focus-aware-polling.test.mjs`：聚焦基础间隔、未聚焦倍率（含 <1 钳制）、空闲截止（含 null 关闭、0 立即）、禁用（≤0）与应用点约定（自动化调度器不受影响）。

# Data recovery, indexed search and portable history

Implementation rules for F-003/F-005/F-006/F-007 (2026-09-26).

- The recycle bin owns a JSONL copy and a versioned sidecar containing its original workspace/path, deletion time, session identity and desktop flags/group position. Legacy files are listed with an explicit metadata limitation. Restoration copies exclusively into the selected registered workspace; a collision never overwrites. Desktop metadata is applied before removing the bin copy. Failure leaves the bin copy available. Repeated restore is rejected. Retention defaults to unlimited; changing retention only selects candidates, and permanent cleanup requires explicit item IDs and a matching deletion timestamp. Running sessions are excluded.
- Search indexes are disposable derived data. Session fingerprints include path, size and modification time; only changed JSONL files are parsed. Results default to the active branch and other branches require an explicit option and carry their branch leaf. Query snapshots have stable result identities and opaque cursors; changed queries cannot reuse cursors. File deletion, editing, branching and metadata updates appear on the next query. Damaged caches rebuild from source without modifying source files. Rebuild/cancellation are explicit operations.
- Project search uses one shared cached path enumeration and configurable ignore/include/exclude rules. It does not follow symlinks. Content search is literal, bounded, case configurable and reports one-based line/column, snippets and skip reasons. Files larger than the configured text limit, binary files and unreadable files are explained. Directory modification fingerprints invalidate cached enumeration on the next query; explicit refresh is also available.
- Native import accepts bounded Pi v1/v2/v3 JSONL after complete header, version, identity, workspace and parent-graph validation. It never executes historical tools. Each import remaps its session identity, preserves branches, and commits a fully flushed temporary file with exclusive creation. Import fingerprints provide idempotent retry. The complete backup format has a separate `pi-desktop-backup` discriminator and version 1; it retains complete raw JSONL, desktop metadata, groups and embedded attachment contents/references. The UI distinguishes it from current-branch JSONL and rendered exports.
- Backup restore validates every item before writing any session. A journal records destination identities before commit; failures roll back newly created session files, and retry completes the same identities. Import into a different workspace requires an explicitly selected destination and rewrites only the session header cwd. Source context attachment references remain historical provenance.
- Permanent cleanup releases the deleted session's input owners and queue journal only after its identity/deletion time and inactive state are confirmed. A surviving original file retains its input scope. Restoration retains input references; restoring into another workspace explicitly warns that drafts and unconfirmed input queues do not migrate. Metadata rollback failures cannot prevent an independent attempt to remove newly imported files.
- Running automation sessions are excluded before index reads, result totals and pagination; changing the excluded set invalidates old cursors. Complete backup refuses any running source, including a background interactive runtime, and repeats that validation after the native save picker. Native import repeats destination workspace validation after its picker. The session index is counted as disposable search-cache storage.
- UI handlers use trusted renderer registration and existing workspace/active-session guards. Search parsing runs in the agent utility process. Tests use real temporary files, simulated EXDEV/ENOSPC failures, branch fixtures and measured cold/warm index reads. Headless renderer fixtures are prepared without starting user software.

# 模型、项目与数据管理及自动化契约

范围：F-011～F-019。本文描述当前源码与已有回归覆盖，不代替发布、打包或线上供应商验收记录。管理操作复用已认证的 renderer IPC、preload 和 agent RPC；不会直接把供应商响应、密钥或模型对象传给 renderer。

## 所有者、存储与兼容

| 功能 | 数据所有者与主要实现 | 持久化及兼容规则 |
| --- | --- | --- |
| F-011 实际推理测试 | agent 会话的 `ModelTestService`、现有 SDK `ModelRuntime` | 测试状态只在内存，不追加会话消息、不修改当前模型。复用已经保存的模型和凭据配置。 |
| F-012 项目默认值 | agent 的 `ProjectDefaultsService` | 读取 agent 目录的全局 `settings.json`，修改项目 `.pi/settings.json`。只替换三项默认值，保留未知及其他配置字段。 |
| F-013 插件准确版本 | agent 的 `pluginUpdates.ts` 与既有插件变更流程 | 预览只在内存；安装成功后替换原作用域 packages 中的来源字符串，保留对象形式的资源过滤规则。 |
| F-014 诊断 ZIP | 桌面主进程 `DiagnosticsService` | `userData/diagnostics/events*.jsonl`；导出 ZIP 带 version 1 清单。日志首次使用时创建。 |
| F-015 真实用量 | agent host 中的 `UsageService`，桌面提供项目和自动化身份 | 读取 agent 目录 `sessions`，缓存到 `desktop-usage-index.json`。缓存 version 2；旧 version 1 或不合法缓存从会话文件重建。 |
| F-016 空间扫描和清理 | 桌面主进程 `StorageService` | 扫描 userData 与 agent 目录；清理计划只在内存，应用重启后必须重新预览。 |
| F-017～F-019 自动化 | 桌面 `AutomationService`、`automationSchedule.ts`、独立 worker executor | `userData/automations.json` 保持 version 1，新增字段可选。已存在任务继续读取，不改写会话格式。 |

管理协议定义在 `packages/shared/src/managementFeatures.ts`，插件版本检查另有 `pluginUpdates.ts`；自动化沿用 shared 中的任务、运行记录与 revision 快照。自动化会话身份另存 `userData/automation-session-ledger.json`，以会话路径标识；创建会话时先登记，完成后补充运行 ID。

自动化旧配置缺省 `misfireGraceMinutes` 表示保留合并补跑一次的行为，缺省 `maxScheduledRuns` 表示无限次数，缺省 `dispatchRetryLimit` 使用最多 2 次安全派发重试。既有累计计数保留；旧的已完成历史记录不回溯推算额度。损坏的自动化状态不能作为空配置静默覆盖，也不能启动执行器。

## F-011：测试实际模型推理

入口是保存后可选的具体 provider/model。agent 调用 SDK `completeSimple`，发送单条 `Reply with OK.`，`maxTokens: 16`、`maxRetries: 0`、20 秒超时，并传入本次请求的 AbortSignal。测试不使用当前对话上下文，也不调用会话的 prompt 流程。界面提前说明可能产生少量费用。

每次请求携带独立 `requestId`，格式限制为 1～100 个字母数字、下划线或连字符；provider 最长 200 字符，model 最长 400 字符。同一个 ID 正在运行时拒绝重复请求，每个服务实例最多同时测试 3 个模型。取消按 ID 命中原 controller；agent 层会向所有保留的会话实例传递取消，因此切换当前会话后仍可取消原测试。实例销毁会中止其全部测试。

成功需要 SDK 返回 `stop` 或 `length` 终止状态，且至少有一段非空文本；并不要求回答逐字等于 OK。找不到模型、空文本、异常终止、解析失败或不完整流返回失败。错误只分类展示 401、403、404、429、超时/取消与通用推理失败，不回传供应商原始错误正文、请求地址或凭据。

首期只测试已保存且可由当前 SDK 解析的模型，不提供未保存表单的临时推理沙箱，不把目录连通性等同于推理成功。服务配置了超时和中止信号；底层协议适配器仍需正常响应中止。测试结果是一次请求的观察，不表示供应商之后持续可用。

## F-012：项目模型与思考级别默认值

项目默认值设置页已按用户要求移除。下述协议、后端服务与测试保留，用于现有项目配置兼容，不再提供该设置页入口。

仅支持 `defaultProvider`、`defaultModel`、`defaultThinkingLevel`。快照同时展示全局值、项目覆盖、当前有效值、文件路径、项目信任状态和配置版本。未受信任项目可读取自身覆盖以解释配置，但覆盖不生效，也不能保存。空字段/恢复继承通过删除相应项目键实现；不会清空整个配置文件。

保存请求绑定 `cwd` 和 `expectedVersion`，版本为项目配置原始文字的 SHA-256。写入在服务队列中串行执行，先检查当前版本，写同目录临时文件并 fsync，再检查一次版本后 rename。外部修改、格式错误、权限或磁盘错误直接失败，保留原配置及用户草稿；临时文件在结束时清理。配置文件要求为不超过 1 MiB 的普通文件，不接受配置文件符号链接或 `.pi` 目录链接。

值只做允许字段、字符串长度和思考级别枚举校验，不在保存时请求远端验证模型能力。普通字符串最多 400 字符，拒绝空白和控制字符。思考级别支持 `off/minimal/low/medium/high/xhigh/max`。

这些默认值用于后续新会话；保存不修改当前会话的模型、思考级别或消息。现有会话自己的选择继续保留。首期不是任意项目设置编辑器，也不编辑 API Key、代理或全局设置。版本比较防止通常的外部编辑冲突，但不声明跨进程文件系统锁或所有文件写入者之间的原子事务。

## F-013：插件版本检查与准确目标安装

检查只支持标准 `npm:` 来源，读取已配置来源及已安装包的 `package.json`，从公共 npm registry 查询元数据。展示已安装版本、来源约束、准确目标版本、latest、检查时间和分类。Git 来源仍以配置 ref 为准，本地来源读取自身文件；两者不会伪装为 npm 可升级版本。

semver 范围选择满足范围的最高版本，标签解析为标签对应版本。固定版本即使已安装也可明确选择同版本修复；另一次“查看最新版本”检查才能得到升级目标。已安装版本高于候选版本显示当前状态，不提供自动降级。缺包显示修复；网络或元数据失败显示“未能检查”，不推断为无更新。

只读检查不调用 install、不修改 packages。请求绑定当前项目、user/project 作用域和原始来源；开始网络请求之前即捕获整个作用域 packages 的指纹，避免检查期间新配置被误认为旧目标的基线。预览有效 10 分钟，最多保存 50 个；registry 超时 15 秒，元数据最多 8 MiB。

确认安装复用插件变更互斥锁、项目身份检查和受信任项目规则，拒绝重复执行同一个进行中的预览。安装目标固定为 `npm:<name>@<exact-version>`。安装后再次读取实际版本，只有与预览一致才替换配置；对象形式中的 extensions/skills/prompts/themes 等过滤字段保留。安装前后都核验配置指纹，外部修改时不会覆盖较新的配置。

配置成功后进入既有跨会话插件重载流程。UI 在成功后清除已消费的预览，即使固定版本修复没有改变来源和版本，也不能重复使用旧确认；检查失败清除旧目标，安装失败保留重试目标。重载阻塞或失败保留准确诊断，不把已经落盘的配置或包安装报告为已回滚。若安装已产生文件变动而版本验证/配置冲突失败，错误明确要求刷新核对；首期不提供包管理器文件树事务或依赖自动回滚。准确版本安装后来源会固定，不继续隐式跟随原 range/latest。自定义 registry、私有 registry 鉴权及 Git 提交更新预览不在本期范围。

## F-014：本地诊断日志与 ZIP

主进程在 startup、rpc、host、plugin 阶段记录白名单字段：时间、阶段、动作、结果、耗时、数字请求 ID 和受限代码。不会序列化完整 IPC 参数、提示词、附件、任意 Error 对象、Authorization 或 OAuth 内容。导出再次从日志逐条重建白名单记录；清单仅附应用/Electron/Node/平台版本和处理信息。

日志串行追加，活动文件达到 512 KiB 后在下一条记录前轮转，最多保留 8 个历史文件及一个活动文件。诊断写入失败不能阻止聊天或应用启动。导出选择最近 1～30 天，原生保存对话框取消时返回空路径，不创建归档。

导出只读取匹配日志命名的普通文件，跳过符号链接、超限或无法读取的文件及损坏记录。归档日志正文预算为 4 MiB；达到上限时跳过文件并列入清单。清单和 ZIP 封装开销不包含在这 4 MiB 正文预算中。损坏行的逐条说明限制为 200 条，多余数量汇总，避免大量坏行造成巨大清单。

ZIP 写入目标旁的唯一临时文件，完成后 rename；失败清理临时文件并返回错误。导出不会自动上传。它是近期结构化事件包，不是完整控制台日志或供应商网络抓包；日志记录失败的时间段不能由导出恢复。停止写入/导出也不清空已有日志。

## F-015：以真实助手消息为来源的用量

从 JSONL 中有 usage 的助手消息取输入、输出、缓存读取/写入 token 和记录费用，包含会话树中真实发生过的分支请求。过滤维度为已登记项目、日期、时区、provider、model 和交互/自动化来源。日期先验证真实日历值，再按请求中的 IANA 时区归日，不用机器当前日期直接截断 UTC 时间。

消息身份由保留的记录 ID、规范时间、provider/model 和 usage 构造稳定指纹。SDK fork 会产生新 sessionId 但复制历史记录；索引读取 `parentSession` 并优先将继承消息归属于原文件，然后去重和应用项目/自动化过滤。这样复制历史不会重复计费，也不会把原任务费用转到分支项目。原父文件仍在扫描范围时保留原始归属；父文件不可用时只能基于现存副本去重，不能重建已经删除的完整来源链。

缓存记录文件 size/mtime/ctime 及提取条目；未变化文件复用缓存，损坏的条目重解析。解析前后文件指纹不同则本次跳过，提示下次刷新。version 1 索引或非法缓存自动重建；缓存不是唯一账本，不更改原会话。会话被永久删除或移出扫描范围后，不承诺保留它的永久消费汇总。

`requestId` 与中止 controller 对应，同 ID 不能重入，最多挂起 3 次请求，实际扫描通过队列串行。取消会中止扫描/流读取；提交索引之前再次检查中止状态。索引用同目录临时文件、fsync 和 rename 保存，写入失败不将新的内存缓存冒充已持久化成功。

单次最多处理 20,000 个会话文件，单文件最多 64 MiB，单行最多 16 Mi 字符；累计新读取量超过 512 MiB 后停止读取后续文件，因此最后一个文件可能使累计值超过阈值。无权限、损坏、超限和正在写入的文件显示为跳过项，结果可能不完整。日期/模型过滤用于汇总，不把缩小日期范围解释为完全免除索引扫描。

费用来源标记为 `session-message-estimate`，不是供应商账单或实时价格查询。缺少合法价格以及无法确认的零价格均计为未知；任何含未知价格的汇总行费用为 null，并保留未知消息数，不显示为免费。没有 usage 的消息不臆造 token 或费用。自动化身份来源于独立持久映射，不靠会话标题猜测。

## F-016：空间统计、预览与精确清理

按 sessions、attachments、trash、diagnostics、search-cache、corrupt-backups、settings 分类统计。首期可清理范围限定为轮转诊断文件、已命名的可重建用量缓存 `desktop-usage-index.json`、会话搜索缓存 `sessions/.desktop-search-v1.json`、根目录中的损坏状态备份；`search-cache` 分类不代表任意搜索数据库都可删除。活动 `events.jsonl`、普通会话、附件、回收站、凭据和设置只统计，不进入此清理计划。

递归遍历预算为 30,000 项、深度 5，最多同时 2 个扫描请求；跳过目录/文件链接和无法读取项，快照带 `limited/skipped`。requestId 防止重复扫描并支持取消，预览中的内容指纹读取阶段也检查取消。保留天数为 1～3650，只选择修改时间早于阈值的允许文件。

每份计划列明绝对路径、分类和字节数，最多 1,000 个文件、10 分钟有效；最多保留 10 份计划。执行只接受服务已保存的计划 ID，不能由 renderer 直接提交任意待删除路径。计划开始执行即消费，同一时间只允许一个清理过程。

计划捕获根目录的 realpath、device、inode，执行时重新检查根身份、每级父目录、目标普通文件类型及 size/mtime/ctime/inode。64 MiB 以内文件还比较内容 SHA-256；更大文件使用元数据指纹。读取后再次核验父目录与目标状态，再 unlink。被替换的 Windows junction、符号链接、已变化文件或越界目标拒绝删除。

结果逐文件报告成功数量、释放字节和失败原因，允许明确的部分成功，不将失败项记为已释放。已成功删除的缓存不回滚，失败后必须生成新计划；执行阶段不提供中途取消/恢复事务。此面板不做自动定时清理；附件回收遵循独立的引用规则，回收站永久清理位于“恢复与搜索”，复用 F-002/F-003 契约。路径核验降低误删风险，但不是对任意外部并发写入者的跨进程删除事务。

## F-017～F-019：同一自动化状态机

每次运行拥有独立 utility worker 和新会话，不向前台对话发送内容事件。设置模型/思考级别只作用于该次 worker，不持久修改交互默认值。项目必须已在侧栏登记；无人值守执行不授予新项目信任，不批准交互式扩展请求。收到交互请求、进程崩溃、取消或默认 30 分钟超时都会进入停止与清理流程。会话路径在 worker 确认退出之前保持占用，未确认退出会阻止后续派发，不能把失联 worker 当成已停止。

最多保存 100 个任务、200 条运行历史；最多同时运行 2 个，不允许同一任务并行重入。任务名称最长 120 字符，指令最长 32,000 字符，运行摘要及错误最长 4,000 字符。淘汰历史只处理已经结束的记录，不能挤掉 running/retrying 记录。任务、状态变更与 tick 通过同一服务队列串行。

领取记录和下次计划时间先持久化，成功后才创建执行流程。运行以稳定 `run.id` 代表一个计划发生次，保留 `scheduledAt`、实际开始/结束、attempts、retryAt、dispatchState、counted、结果会话及状态；renderer 用 revision 快照识别较新状态。单次手动运行不改写已有计划时刻。

### 过期补跑与时区（F-017）

`misfireGraceMinutes` 缺省/null 时，应用恢复后将错过的多个周期合并补跑一次，再推进到未来，不逐条追赶积压。配置宽限为 1～525,600 分钟；超过宽限则写一条 skipped 记录，记录计划时间、处理时间和原因。重复计划推进一次到未来，单次计划跳过后禁用并完成，跳过不消耗执行次数。

间隔计划支持 5 分钟～30 天；每周计划使用明确时区、星期和 HH:mm。夏令时不存在的本地分钟跳过，重复本地分钟只取第一次，不执行两遍。单次日期要求带时区偏移或 Z，保存为 UTC ISO，拒绝不可能的日历日期。调度只计算严格晚于给定时间的下一次发生。

### 只重试尚未派发的瞬时失败（F-018）

派发状态为 `not-started → dispatching → accepted`。调用 prompt 之前先持久化 dispatching，RPC 接收后再记录 accepted；RPC 接收不等于任务完成，executor 继续等真实 idle/error 状态。SDK 自己的模型响应重试仍由 SDK 管理，不被这里套成整任务重跑。

只有明确 `executionStarted === false`、仍处于 not-started，且错误码属于 `ECONNRESET/ECONNREFUSED/EPIPE/ETIMEDOUT/ERR_WORKER_INIT_FAILED` 时才允许自动重试。已调用 prompt、接收回执丢失、执行状态不确定或工具已经可能运行的情况不会自动重放。永久配置/鉴权错误也不纳入此派发重试。

`dispatchRetryLimit` 为 0～5，默认 2；包括初次执行最多 6 次尝试。重试继续使用同一个 run.id 和计划发生次，attempts/retryAt 持久化，退避公式为 `min(300000, 5000 × 2^(attempts-1))` 毫秒。服务重启保留已写入的 retrying 与退避时刻；原 running 一律标记 interrupted，要求用户决定后续，不因重启自动重跑。

用户暂停任务会取消尚未派发的重试，并禁止正在初始化的尝试随后安排新重试；不会自动中断已发送模型的工作。显式取消运行中止其 controller，并等 worker 释放。删除任务前必须先停止 running/retrying。插件维护或未退出 worker 会暂缓新派发；维护发生在领取之后但实际执行之前时，调度恢复原发生次，同时保留后来用户编辑的优先级。

### 次数上限与失败持久化（F-019）

`maxScheduledRuns` 为 1～100,000，缺省/null 无上限；`scheduledRunCount` 持久化，达到上限后禁用任务、清空 nextRunAt 并记录 completedAt。手动运行、skipped、维护延期和派发前重试不占额度。同一发生次用 counted 标记至多累计一次，正常在 accepted 时计数。

对于已经进入 dispatching 的不确定失败或应用退出，保守计入一次，避免在可能已执行后因额度漏记而多派发。计数不是“模型成功回答次数”。已完成任务保留历史和计数；提高上限后可重新启用，降低至不大于已用次数则保持完成。完成卡展示单独提示并禁用直接启用，用户可进入编辑调整计划或提高上限后启用；手动运行仍可用。首期没有结束日期或自动重置累计数。

写入领取状态失败时不启动模型。完成/接收状态写入失败时，内存保留待持久化结果及计数，暴露 storage error，并阻止新派发；随后 tick 或用户操作先尝试写回，不再次执行已完成任务。暂停、取消和后续编辑不会被晚到的恢复结果覆盖。退出服务中止活动运行并等待清理和最后写入；无法写入的状态错误继续报告，不能报告为成功落盘。

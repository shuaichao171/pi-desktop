# 输入可靠性与文档处理

范围：F-001、F-002、F-008、F-010。F-009 输入历史已按用户要求移除。现有 Pi JSONL 附件、8 MiB 历史预算与 20 MiB 按需读取保持兼容。

## 队列账本与 SDK 边界

应用账本以输入 ID、请求 ID、队列版本及完整预处理后载荷为身份。当前固定 SDK 0.87.1 的公开队列修改 API 会异步重新运行扩展，因此适配器在受检的 PendingMessageQueue enqueue/drain 边界工作。修改同步替换未消费对象和 SDK 显示镜像，不清空重建、不重新执行输入扩展，也不按文本寻找目标。

接受前落盘；消费前写 reserved，message_start 写 consumed。更新先持久化再原子提交内存，失败保留原队列。相同 requestId 重试只应用一次并返回当前队列快照；版本过期、已 reserved 或 consumed 不可修改。已知未接收的拒绝允许原输入 ID 再试；已接收、已消费或用户明确删除的输入不会重放。重启后 accepted/reserved 都恢复为 recovered 待确认，禁止自动重放不确定是否已执行的输入。明确确认才重新排入；删除可放弃恢复项。每会话最多 100 个待执行输入、5,000 条输入回执及 5,000 条变更回执，终态不继续保留附件载荷。

暂停使 follow-up drain 返回空数组且 hasItems 不触发 SDK 的自动续跑，当前任务正常完成，steer 继续遵循抢先输入语义。恢复由适配器启动空闲队列，已开始的项目不重放；排序仅作用于同类型未消费条目。后台会话保留自己的暂停标记和账本。

## 附件与草稿

附件存入 Pi agent 目录下的 `desktop-inputs/attachments` 受限仓库，以内容 SHA-256、版本、类型、名称、大小标识；内容变化产生不同身份。每附件编码载荷不超过 20 MiB、仓库最多 256 MiB、单草稿最多 12 份。工作区和会话范围限定访问；正文及附件引用作为有版本草稿事务保存，旧纯文字 localStorage 草稿可迁移。孤立暂存内容保留 24 小时，删除草稿/队列只释放自身引用，不删除其他引用仍在使用的内容。缺失内容返回明确 missing 状态，发送必须先解决，不能悄悄丢附件。

## 输入历史移除

聊天输入框不再提供已发送输入历史入口、浏览或复用功能。普通草稿及附件持久化、对话记录和队列编辑保留。

## PDF 首期

只支持本地提取文字 PDF，不声明原生模型文档输入或 OCR。PDF 在可终止处理任务中解析：20 MiB 原始文件、100 页、200,000 字符、20 秒预算；页码和文档名写入文本。扫描页/截断明确显示；全扫描、加密、损坏及超页数拒绝添加。取消和失败保留原草稿。解析禁用执行脚本及远程资源，用户确认的本地上传数据不会触发外部 URL 加载。

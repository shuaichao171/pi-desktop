# 工作台与搜索交互规范

实现范围：UI-009、UI-010、UI-013、UI-020、UI-021、UI-022、UI-023。复用现有受限文件读取、Git 操作与命令执行接口；保留主进程原生命令确认和输出上限。

## UI-009：覆盖模式焦点

- 1100px 以下工作台使用 `dialog`/`aria-modal`，打开后焦点进入工作台。Tab 和 Shift+Tab 在可见可用控件之间循环，外部程序聚焦也会被收回。已聚焦控件卸载时回到首个控件。
- Esc 关闭并在关闭后的帧恢复工作台触发器。文件菜单先处理自己的 Esc；工作台输入和查找按键不会冒泡到聊天快捷键。
- 1100px 以上保持并排 `complementary`，允许正常跨栏访问。设置、搜索在上层时工作台 inert 并暂停焦点约束；原生扩展模态层也优先。
- 覆盖模式工作台优先于窄窗侧栏，打开时收起窄窗侧栏。

验收：场景在 1440px 验证聊天输入可聚焦；900px 验证 Tab、Shift+Tab、Esc 与焦点返回；680px 验证覆盖及放大预览。

## UI-010：文件与差异阅读

- `WorkbenchTextView` 为文件和 unified diff 提供固定标题、行号、增删背景、原文复制、字面查找与逐次跳转。Enter/Shift+Enter 切换命中，Ctrl/Cmd+F 聚焦阅读器搜索。
- parser 按 hunk 行数计算旧/新行号。双语来源标题、重命名元数据、无末尾换行标记和截断说明不当成代码，也不伪造缺少的上下文。
- 文件高亮复用 highlight.js 与主题语义色；超过 100,000 字符使用纯文本，避免高亮阻塞。首次显示 2,000 行，可继续展开；查找覆盖已读取全文并自动显示目标行。
- 复制使用接口返回原文，不混入行号和高亮标记。服务端限额说明持续可见，复制当前预览不代表完整文件。

验收：`workbench-reading.test.mjs` 覆盖双语分段、增删与重命名元数据、中文、CRLF、正则字符字面搜索、截断；headless 场景检查真实行号/增删行及两个命中的跳转。

## UI-013：尺寸与比例

- 宽度独立保存为 `pi-desktop.workbench-width`，默认 420px，正常偏好范围 320–800px。宽窗至少给主栏留下 480px，覆盖模式按视口约束；缩窗不覆盖保存的宽窗偏好。
- 左边分隔线可拖动，左右键每次 16px，Home/End 到边界。拖动时禁用工作台尺寸过渡，不卸载工作台或聊天内容。
- 列表与预览比例保存为 `pi-desktop.workbench-preview-ratio`，范围 25–80%，默认 54%。横向分隔线可拖动，上下键每次 5%，Home/End 到边界。
- 预览可放大并返回列表，保留文件、查找和列表状态。标题、路径使用语义 UI 字号；文件/diff 用 `--pd-code-font-size`，命令正文用 `--pd-command-font-size`。

验收：纯函数验证 680/1280/1440 的尺寸边界；headless 验证键盘调整、存储及 680px 放大/返回。拖动复用 pointer capture，取消捕获会清理拖动状态。

## UI-020：失败分组的键盘重试

- 会话和文件搜索分别拥有请求效果及重试计数。失败项作为对应分组的可导航 `option`；上下键可选择，Enter 重试。
- 重试只刷新失败源，不清空已成功源，不关闭搜索框；保留查询、范围和稳定行身份。请求中禁用该重试项，完成状态由独立 `role=status` 播报。
- 换查询/范围/工作区后的旧请求由各自取消标记忽略。

验收：`search-selection.test.mjs` 实际驱动组件效果与键盘事件，确认会话失败后重试使会话调用 2 次、文件调用仍为 1 次；成功文件行身份持续存在。

## UI-021：Git 分组与差异来源

- 已暂存组读取 X 列，未暂存组读取 Y 列并包含 `??`。`MM` 同时出现在两组；组标题显示数量，状态有可读名称。
- 已暂存行提供取消暂存，未暂存行提供暂存；已跟踪未暂存内容保留丢弃确认。丢弃继续使用 index 作为工作树恢复来源，不丢弃已暂存内容。
- `getWorkspaceGitDiff(path, source?)` 从 preload/IPC 贯通服务端，`source` 允许 `staged`、`unstaged`、`all`，省略时兼容原来的 `all`。服务端拒绝其它值，未跟踪文件的 staged 来源返回空。
- 选中来源体现在差异标题与实际返回内容；操作后刷新分组和当前来源差异。

验收：真实临时 Git 仓库测试 `MM` 的两类 patch 互不混入，原来的合并预览仍兼容；headless 检查 `M `、` M`、`MM`、`??` 归组和实际 source 调用。

## UI-022：文件导航与菜单

- 列表仅当前行进入 Tab 顺序；上下键、Home/End 遍历，Enter/右键箭头打开，左键箭头/Backspace 返回父目录。目录切换结束后焦点回到首行，空目录可聚焦列表。
- 右键、Shift+F10 或行尾菜单可复制完整路径、在编辑器打开、在资源管理器定位。菜单显示完整目标路径，Escape 返回原行，方向键切换菜单项。
- 原生打开失败进入共用反馈；重试闭包绑定原路径与工作区，已切换工作区则不执行错误目标的重试。400 项上限与不可读目录提示继续保留。

验收：headless 通过真实键盘导航进入/退出目录、打开菜单，确认菜单目标以及 Escape 返回的行。

## UI-023：命令输出阅读控制

- 输出正文没有 `aria-live`，运行/停止/退出状态单独播报。stdout/stderr 保留原始换行，stderr 维持错误色。
- 初始跟随底部；上滚暂停，流式追加不会强制回底；回到底部按钮恢复跟随。复制当前保留的原文，查找定位每次命中。
- 最多保留 120,000 字符/512 事件；实际移除内容时记录遗漏状态并显示提示，不能仅根据当前长度猜测。
- 清空显示删除当前显示的输出，保留运行身份和结束状态，不调用停止；后续输出仍接入同一运行。停止按钮继续可用。

验收：纯函数验证缓存截断、stderr 范围与终态；headless 验证上滚后追加、恢复跟随、超限提示、清空不停止和显式停止。

# 工作区切换时的 Git 操作边界

丢弃确认保存工作区和相对路径，切换工作区或 bridge 后清空确认、分支表单及 Git 状态。暂存、丢弃和创建分支共享同步操作锁；每个异步结果必须仍属于原工作区、原 bridge 和原操作，才可以刷新状态、更新错误或关闭表单。工作区导航进行中不接受新的 Git 修改操作。

回归场景 `tests/fixtures/ui-improvements/workbench-workspace.mjs` 覆盖 A 待确认切 B 不发丢弃、A 暂存晚完成不刷新 B、A 丢弃晚失败不覆盖 B 确认，以及 A 建分支晚完成不清空 B 草稿。脚本的 31 条浏览器表达式通过静态编译，实际 renderer 验证由主代理统一执行。
